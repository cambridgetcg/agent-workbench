# Agent Workbench 0.5.2

Follow-through on PR #3 (live worktree state and removal of pushed trees),
after a survey of the installed caches and the run records on 2026-10-28.

- The plugin caches never picked up PR #3. It changed code and skill text but
  kept version 0.5.1, and Claude Code and Codex key their caches by version, so
  both kept serving the earlier files: the skill they served still lacked the
  line "Never use `git worktree remove` on Workbench trees". This release
  changes the version everywhere: 0.5.2 in `pyproject.toml`, the package and
  the Claude manifests, and `0.5.2+codex.20261028120000` in the root and Codex
  manifests, which must stay identical because Codex names its cache directory
  after that exact string.
- `explain` now compares agent-workbench's caches with their source by content,
  not only by version. Each Claude registration row of agent-workbench, and a
  new Codex row for `$CODEX_HOME/plugins/cache/*/agent-workbench/<version>`,
  reports `content` as `match`, `differs` or `unknown`, with file counts. The
  digest covers the served scope (`agent_workbench/**/*.py`, `scripts/`,
  `skills/` and the plugin manifests) and reuses the evaluation payload hasher
  through `payload_digest`, whose whole-tree digest is unchanged, so saved
  evaluation plans stay valid. Symbolic links are refused, never followed.
  The Codex row's source is agent-workbench's Claude directory-marketplace
  source when one is registered, else the tree running `explain`; a source
  inside either harness's plugin cache is never compared (`source_is_cache`),
  since the bundled script can run from a cache and two equally stale caches
  would read as a match. The comparison reports no path, file name or content.
  Other plugins show `not_compared`.
- `workspace-remove` closes the record of a worktree already deleted outside
  Workbench. 32 records claimed trees that were gone (29 command-harness trees,
  28 of them recorded dirty, and 3 Astra trees), and each was refused, because
  removal required the tree to exist. When nothing is at the recorded root, the
  same lock, activity and ownership-path checks run, then Git must confirm the
  tree is unregistered: `git worktree list --porcelain` must not list it and
  no admin entry's `gitdir` may name it. A still-registered tree is refused
  with `registered_but_missing`; Workbench never prunes. A source repository
  that is missing, or where Git fails, is refused with
  `source_repository_unavailable`, so a failure never reads as "not listed".
  The closed record has `removal_basis: absent_outside_workbench`,
  `removed_head: null` (the HEAD at removal was never observed),
  `last_recorded_head`, `final_head_on_remote_ref`, `recorded_dirty`,
  `observed_absent_at` and `possible_unpushed_loss`, which the command prints
  plainly when the attempt ended dirty or its last recorded HEAD is not known
  to be on a remote-tracking ref. For this basis `removed_at` is when the record
  was closed.

Synthetic tests cover each closure and refusal with real Git worktrees
(unregistered, still listed, named only by an admin `gitdir`, missing or
enclosed source, a foreign directory or link at the root, running or stale
attempts), and content comparison with fake homes (match, a one-byte or
mode-bit difference, a missing cache and symbolic links that are not followed).

This is an agent's call under Yu's 2026-10-28 word and the 2026-10-20
delegation; ledger hx-workbench-truth-retention. To undo it, revert the release
commits (or the merge that lands them); a reverted install also needs its
caches refreshed, since the version changes back.
