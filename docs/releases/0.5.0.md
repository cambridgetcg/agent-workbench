# Agent Workbench 0.5.0

This release closes gaps found when Workbench was first used to invite a native
Hermes agent into a multi-step project. Worktree tasks can start from a chosen
revision and record what each attempt left behind. Codex read-only tasks are
sandboxed, and Hermes tasks can carry the options long work needs.

- `base_ref` selects a worktree task's starting revision, such as `origin/main`,
  instead of whatever the source checkout has checked out. `create --base-ref`
  sets it for a single task.
- After every worktree attempt, once its processes have ended, Workbench records
  final HEAD, branch, commits ahead and behind the base, dirtiness, entry counts,
  and tracked file, insertion and deletion counts. It stores no file names or
  contents. A Git or ownership failure marks the evidence unavailable without
  changing the outcome. Dependent agent prompts receive this as a separate block
  labelled as Workbench's record, apart from the predecessor's own summary;
  nothing is merged automatically.
- Codex tasks declared `read-only` launch with `--sandbox read-only`. A Codex
  task's `sandbox` selects `workspace-write` or `danger-full-access` explicitly;
  otherwise Codex's configuration still applies. Under `workspace-write`, a
  worktree task can edit but not commit, because Git metadata lives in the
  source repository; Workbench deliberately does not widen that boundary.
- Hermes tasks accept `max_turns`, `skills` and `run_budget_seconds`, forwarded
  as `chat --max-turns`, `--skills` and `--run-budget`. The budget must be
  shorter than the task timeout so Hermes can wrap up before the hard stop;
  `run --timeout` must be longer still. `create --timeout-seconds` sets a single
  task's timeout.
- Hermes's own file-mutation verifier footer becomes a result warning, so a
  failed native file edit is no longer recorded as clean success.
- Hermes text deltas become one timeline event per contiguous run, so tool
  events stay inside the 2,000-event journal. Polling no longer rewrites run
  state on every 50 ms cycle; lifecycle boundaries still flush immediately.
- A single-task run whose goal repeats its prompt sends that text once.
- Native tasks, plugin evaluations and mod checks no longer inherit the
  launching Claude Code session's identity and messaging variables: `CLAUDECODE`,
  `CLAUDE_PID`, `CLAUDE_EFFORT`, `CLAUDE_CODE_SESSION_ID`,
  `CLAUDE_CODE_CHILD_SESSION`, `CLAUDE_CODE_SESSION_ATTENDED`,
  `CLAUDE_CODE_ENTRYPOINT`, `CLAUDE_CODE_EXECPATH` and every
  `CLAUDE_CODE_MESSAGING_` variable. A task's launch record lists the removed
  names; other variables, including API keys, are still inherited.
- Run launches no longer probe `hermes --version`, which performs Hermes's
  upstream update check; `explain` still does.
- Git helpers run with `GIT_OPTIONAL_LOCKS=0`, so worktree preparation cannot
  briefly hold a shared checkout's index lock.
- A checkout claim that disappears after an attempt begins now finishes that
  attempt as `workspace_busy_after_attempt` instead of leaving it running.
- `workspace-remove` refuses worktrees with ignored files, which Git would
  otherwise delete without warning. Its checks and the evidence pass
  `--untracked-files=normal`, so `status.showUntrackedFiles=no` cannot hide files.
- `doctor` reports a version printed by a failing command as `unverified`, and
  shows whether `OPENAI_API_KEY` or `CODEX_API_KEY` is present (never values), in
  both text and JSON. `explain` lists `~/.claude/CLAUDE.md` once for projects
  under the home directory, while still listing AGENTS.md files that are
  symlinks to a CLAUDE.md.

Synthetic regression tests cover each change, using real Git worktrees for the
base, evidence (including its unavailable and failed-attempt paths) and removal
guards.
The `workspace-write` commit boundary was checked by hand with `codex sandbox`
from Codex 0.156.1 against a worktree of a repository under the home directory.
