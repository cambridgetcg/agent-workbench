# Agent Workbench 0.4.0

Hermes can now run as a native task in shared Workbench workflows, including the
dedicated `hermes-astra-ultra` subscription profile. This release adds a portable
Agent Plugins v1 manifest so Hermes can load the same Workbench skill used by
Codex and Claude Code.

- Native stream result validation, session tracking, public metadata events,
  launch evidence and owned-process cleanup cover both Hermes harness names.
- The access-only token helper pins the existing ChatGPT account, delegates
  refresh to official Codex and exposes a separate read-only diagnostic mode.
- Doctor reports Hermes executable presence and safe binding metadata without
  triggering Hermes's network-capable version check or credential refresh.
- The source map and declaration inventory explain Hermes modules, tools,
  configuration surfaces, delegation and durable state at an exact upstream pin.

Live verification includes a native subscription conversation and a Hermes task
followed by an independent command verifier. A separate credential-free native
request capture verifies `gpt-6-astra`, configured `ultra` → request `max`,
`store: false`, and the exposed main-request tool schemas. The capture proves
request formatting, not every tool's readiness. Synthetic regression tests
exercise malformed terminal results, literal prompt input, cleanup, retry,
account binding and refresh ownership. The local suite passes 292 tests; plugin
and skill validation also pass.

Hermes remains a process adapter; Claude duplex controls and plugin evaluator
support are not implicitly extended to it. Native Hermes approvals remain in
force. See the [Hermes guide](../hermes.md) for setup, use and limitations.
